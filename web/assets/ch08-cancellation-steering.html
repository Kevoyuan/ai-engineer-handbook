Cancellation、Interruption 与 Steering：停止的是 Runtime，不是 UI §8.T

用户点停止之后，真正需要回答的是：哪些工作属于这次 run、取消信号传到哪里、已经开始的副作用处于什么状态、会话协议如何修复，以及新输入是 Cancel、Steer 还是 Follow-up。

FIG.8.T1 · CANCELLATION SCOPE

Cancel 是层级 Runtime Signal，不是一个全局 Boolean

父 scope 取消时终止 owned descendants；单个 child 的取消不应无条件杀掉 siblings 或整个 session。

ROOT · RUN SCOPE

Cancel Request → Stop New Work

用户取消、Timeout、Policy、Supersession 或 Host Shutdown 都可以触发 scope，但 reason 必须保留。
MODEL

Stream / Retry / Backoff

abortable request · retry wait · compaction · next model call
TOOLS

Tool Batch / Tool Child

dispatch boundary · per-tool child signal · no new calls after cancel
OS / REMOTE JOB

Owned Execution Tree

process group · container job · browser session · remote cancel handle
SUBTASK

Foreground vs Detached

Foreground 通常继承 parent；Background 必须有独立 lifetime 与 cancel handle。
核心规则

Every blocking boundary must either accept cancellation directly or race against a cancellation signal.

FIG.8.T2 · INTERRUPTED TOOL TRUTH MODEL

中断后先判断 Tool 执行到哪，再决定是否 Retry

NOT STARTED

Rejected / Cancelled Before Run

没有副作用，可以给协议补 cancelled/rejected result，再重新决策。
STARTED · ABORTED

Partial / Unknown Effect

工具已经开始，不能声称“没执行”；需要检查文件、进程、远端系统或业务状态。
RESULT LOST

Completed? Ack Missing

远端动作可能已提交但本地没拿到结果；先 reconcile，禁止 blind retry。
COMPLETED

Trusted Result Available

有完整、可信的 result，正常提交给 conversation / workflow state。
SIDE-EFFECT BOUNDARY

Cancellation changes control flow; it does not retroactively erase side effects.

TRANSCRIPT REPAIR

补齐 tool_result 是为了恢复 provider protocol；synthetic result 必须写真实 execution state，不能为了让下一轮 API 接受就伪造“没有执行”。

FIG.8.T3 · USER CONTROL SEMANTICS

Cancel、Steer、Follow-up 不是同一个“用户又发消息了”

CANCEL

Terminate Current Scope

停止新工作 → 终止 owned execution → reconcile → repair protocol → quiescent。
STEER

Change Next Decision

当前 action/result protocol 到达安全边界后注入；已经发生的 Tool / side effect 仍然要进入下一次决策。
FOLLOW-UP

Queue After Completion

当前 run 完成 pending work 后再启动新的要求，适合“做完这个，再做那个”。
SAFE INJECTION BOUNDARY

tool_use → tool_result → steering → next model call

不要把普通用户消息任意插进尚未闭合的 Tool 协议单元；先让 action/result correlation 变成 coherent state。
最终原则

Cancellation is complete only when the execution scope is quiescent and its state is trustworthy.

FIG.8.T4 · CANCELLATION LIFECYCLE

UI 可以先显示 Cancelling，但 Runtime 不能立刻标成 CANCELLED

RUNNING

Work Is Active

CANCEL_REQUESTED

Stop Launching New Work

TERMINATING

Abort Requests · Stop Tools · Kill Owned Jobs

RECONCILING

Repair Transcript · Verify Side Effects

QUIESCENT

CANCELLED / FAILED / HUMAN ACTION

两种延迟

cancel_ack_latency 衡量 UI/Runtime 多快接受取消；cancel_to_quiescence_latency 衡量真正停止并恢复可信状态需要多久。
