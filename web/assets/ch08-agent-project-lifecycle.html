Agent Project Engineering Lifecycle：从 Demo 到可维护系统 §8.P

能调用模型和 Tool 只说明执行链路存在。真正可维护的 Agent 项目还需要任务契约、仓库规范、运行拓扑、能力契约、状态生命周期、评估证据和生产反馈。

FIG.8.P1 · AGENT PROJECT ENGINEERING LIFECYCLE

十个教学步骤，收敛成五个工程阶段

这不是一次性的 waterfall。Eval、Trace 与 Production Failure 都可以把工作送回更早的错误层。

DEFINE

Task Contract + Repository Contract + Architecture

Goal · Input · Output · Boundary · Success Criteria；再明确目录、测试命令、依赖/Secret 规则、模块职责和失败路径。
BUILD

Agent · Tools · Skills · Context / Memory · Prompt

Agent 负责不确定判断；Workflow 负责显式控制；Tool 提供单一能力；Skill 固化方法；State/Memory 管信息生命周期；Prompt 作为版本化行为配置。
VERIFY

Test + Eval

Test 验证程序契约；Eval 验证任务行为。固定 Dataset 让模型、Prompt、Skill 与 Workflow 版本可以被真正比较。
OPERATE

Deploy · Trace · Monitor

把 request、workflow state、Agent decision、Tool I/O、版本、Token、Latency、Cost 与 Task Outcome 连到同一条可诊断链路。
LEARN ↺

Root Cause → Dataset → Fix → Regression

生产证据应回到最早错误层：错误 State 修 State；错误 Tool 修 Tool；过时数据源修数据源；不是所有问题都回去改 Prompt。
工程目标

Make uncertain model behavior reliably serve a bounded, testable, observable business task.

FIG.8.P2 · RESPONSIBILITY BOUNDARIES

别把所有东西都叫 Agent

长期可维护性来自责任边界：谁负责判断、谁负责执行、谁保存状态、谁验证成功。

组件 负责什么 不应该偷偷负责什么
Workflow顺序、分支、重试、回退、停止开放式业务判断
Agent不确定判断、规划、诊断、选择隐式拥有全部流程和权限
Tool单一、可测试的外部操作完整任务方法
Skill经过验证的可复用任务方法协议或最终授权
Context / State当前任务真正需要的信息与执行状态无限历史堆积
Memory经筛选的长期有用信息所有临时结果和错误
Test / Eval程序契约 + 任务行为证据凭感觉判断“更聪明”
项目规范

Coding Agent 的项目指令文件应保持精炼，并指向真正的架构、测试和产品文档。以 Codex 为例，AGENTS.md 是官方支持的项目指令机制，但它不是所有 Agent 工具的统一标准。
