Agent Runtime Control Plane：环境上下文 + Identity / Policy §10.R

代码仓库只是显式输入。真正可交付的 Coding Agent 还需要可复现的项目运行上下文，以及独立于模型的身份、授权和凭据控制链。

FIG.10.R1 · PROJECT RUNTIME CONTEXT

Repository 之外，还有一整层“让项目真正跑起来”的隐式上下文

TOOLCHAIN

runtime · build tools · plugins

versioned image / setup
CONFIG / DATA

env schema · DB baseline · migrations

safe defaults · fixtures · seed data
DEPENDENCIES

services · mocks · network policy

allow / deny · upstream / test double
FEEDBACK

logs · health · exit status

structured evidence for repair
VERIFICATION

test · lint · integration · artifact

reproducible completion evidence
SANDBOX

isolation · lifecycle · resource limits

Sandbox 是边界；Runtime Context 是项目语义。
核心原则

Execution environment is part of the task input.

FIG.10.R2 · IDENTITY / POLICY MAIN PATH

模型提出意图，PEP / PDP / Credential Broker 决定真实执行权

IDENTITY

user + stable agent + runtime + task delegation

谁在行动、代表谁、为什么行动。
PEP

resolve actual resource + requested action

靠近执行点，不直接相信模型提供的 resource id。
PDP

policy decision

identity ∩ capability ∩ platform ∩ delegation ∩ runtime
CREDENTIAL BROKER

short-lived · scoped · target-bound

长期凭据留在可信控制面，不进入 Agent Context。
RESOURCE

execute + audit + revoke / expire

tool · API · DB · deployment · MCP server
最终原则

The model proposes intent; the enforcement point resolves and authorizes the real resource.
