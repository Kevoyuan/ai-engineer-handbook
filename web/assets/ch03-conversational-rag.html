多轮 RAG：指代消解、会话状态与独立检索 Query §3.7

“它”“这个”“第二条”这类表达对人类依赖会话即可理解，但对 Retriever 往往不是完整 Query。生产级多轮 RAG 不应把全部历史直接拼给检索器，而应先把会话转换成结构化状态，再恢复当前轮的独立检索语义。

Failure发生位置典型表现

state_stalenessConversation state用户纠正或换题后，旧实体仍继续生效

context_pollutionGeneration context无关历史或旧前提干扰最终回答
CANONICAL RULE

Conversation history is not retrieval state. 把对话压成明确的 topic / entity / constraint state，再从相关状态生成 standalone retrieval query。Topic switch 失效的是 topic-scoped working state，不是所有 Memory。

EVAL

不要只看最终 Answer。单独评估 Referent Accuracy、Standalone Query Constraint Recall、Target-document Recall@K、Topic-switch State Leakage Rate 和 Entity-mismatch Rate，才能定位问题发生在 state、rewrite、retrieval 还是 generation。
