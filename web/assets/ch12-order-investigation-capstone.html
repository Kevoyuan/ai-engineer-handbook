CDC / Delta：证据的时间与来源比模型更重要 03

OMS / WMS / carrier source events
  → raw append + source offset (Bronze)
  → schema / event-ID dedup / tombstone / replay (Silver)
  → governed order timeline + business semantics (Gold)
  → index only optional policy documents
字段为什么必须存在最容易出错的地方
source_event_id重试幂等、证据引用一个 ID 重用不同 payload
source_version某个来源的版本次序跨来源比较版本号
event_time_utc业务事件声称发生的时间把时钟偏差当真实异常
ingested_at_utc观测到的写入时间当成 event time 排序
tenant_id隔离/授权边界来自模型、缺行级策略

官方 Delta 文档明确说明：CDF 不是默认开启、仅记录启用后的更改，历史受保留策略限制。长期审计必须另行存档；不能把 CDF 当成无限期的原始事实库。

Failure Injection：出现问题必须知道在哪一层修 06

场景 A · Carrier Event 晚到/重复

保留 event time 与 ingest time；重复事件必须幂等，冲突 payload 必须隔离。先修 CDC 数据契约，而不是修改 Prompt。

场景 B · 同一个订单号跨租户重复

没有可信 Tenant Context 的查询必须失败。测试检索候选、最终证据、缓存及可观测日志，不能只检查最终 LLM 回复。

场景 C · HANDOFF 记录缺失

输出 INSUFFICIENT_EVIDENCE、缺失事件与下一步人工核对，不可编造一个完整时间线。

场景 D · 退款 Tool 超时

首期根本不开放退款。若后期接入，超时意味着结果未知；需授权审批、持久化操作 ID、下游幂等契约与对账，不能无限重试。

用于估算的示例：若人工平均调查 12 分钟、Copilot 复核总计 5 分钟，则推导节省 7 分钟——这只是算术情景，不是实测结果。真实 Pilot 必须匹配任务难度，记录尾延迟、拒判与安全失败。

关键边界

面试回答优先级：澄清真实问题 → 明确权限与事实来源 → 最薄闭环 → 拒判/安全关卡 → Golden Eval 与成本 → 逐步上线与交接。不要先背技术栈。
