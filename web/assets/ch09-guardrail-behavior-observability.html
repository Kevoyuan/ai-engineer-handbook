Guardrail Evidence Gate + Behavior Observability §9.G

生产级 Agent 不只需要“系统是否健康”的可观测性，还需要“这次任务为什么这样执行”的行为证据；高风险动作则应绑定版本化规则、不可变动作快照和 Evidence。

FIG.9.G1 · BEHAVIOR OBSERVABILITY

Session → Task → Trajectory → Step → Outcome

SYSTEM OBSERVABILITY

系统运行是否健康？

latency · throughput · errors · resource · cost · cache · availability
BEHAVIOR OBSERVABILITY

任务为什么这样执行？

trajectory · tool choice · state change · evidence · recovery · outcome
TRACE vs TRAJECTORY

Trace = operational call graph. Trajectory = task-semantic execution record. 二者可以共享 trace context，但不是同一个概念。

FIG.9.G2 · GUARDRAIL EVIDENCE GATE

Spec + ChangeSet + Evidence → PASS / BLOCKED / UNKNOWN

RULE

GuardrailSpec@revision

固定检查目标、判定标准和 Evidence requirement。
ACTION SNAPSHOT

immutable ChangeSet@digest

把“准备执行什么”冻结成不可变上下文，防止检查对象漂移。
EVIDENCE

Agent Submission(s)

source · observation time · scope · result · failure reason
GATE

PASS · BLOCKED · UNKNOWN

UNKNOWN ≠ PASS. 证据不足时 hold / escalate，不放宽标准。
COMMIT

执行方重新校验当前现实状态

permission · resource version · target · action · duplicate risk
权限边界

Evidence collection can be delegated; authority to commit remains with the control plane.
