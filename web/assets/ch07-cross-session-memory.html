Cross-session Memory：跨会话记住的是受治理的状态 §7.X

“预算不能超过 5000”是否应该跨会话记住，先看 scope 与 durability：它可能只是当前任务约束，也可能是项目级硬约束或稳定用户偏好。Memory 的核心不是存储介质，而是 promotion、scope、provenance、conflict 和 retrieval policy。

FIG.7.X1 · CROSS-SESSION MEMORY GOVERNANCE

写入要晋升，读取要路由，冲突要保留 lineage

长历史摘要只是 Context View。真正 durable 的约束应有结构化 scope、provenance、validity 与 supersession。

WRITE 01

Candidate Extraction

从用户显式陈述、Tool observation 或模型推断中提取候选记忆，并先标记 source_kind。
WRITE 02

Scope + Durability Gate

判断 task / thread / project / user / tenant scope，以及 temporary / stable / expiring。只有真正 durable 的信息进入长期存储。
STORE

Durable Memory + Provenance

保存 value 之外，还保存 source、confidence、valid_from / valid_to、supersedes、sensitivity 和 owner。
READ

Memory Route + Filters

当前 Decision 先决定需要哪类 Memory，再做 scope、permission、validity、relevance 过滤；不是对所有历史做一次全局向量搜索。
CONFLICT

Authority + Supersession

explicit correction、scope specificity、source authority、valid time 与 confidence 一起决定当前有效值；newer 不自动等于更 authoritative。
核心原则

Write selectively. Read selectively. Expire explicitly. Correct with lineage.
