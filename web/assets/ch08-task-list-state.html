Task List：执行进度的会话状态 · §8.14.20

长任务中的清单让 Agent 重新看见目标与未完成步骤，也让用户看到可以纠正的进度。清单是执行状态的视图；Workflow State、持久交接和实际完成验证仍由运行时负责。Manus 反复更新 todo.md 以把目标带回近期上下文，这是团队实践，不是所有模型都能避免目标漂移的保证。

DeepSeek Harness 的 todo_write 每次提交完整清单，每项只有 content 和 pending / in_progress / completed。实现会拒绝空白或重复描述及未知字段。allowParallelInProgress 是部署时必选的设置：false 时拒绝超过一个活动项，true 时允许多个；这个开关不能观察或证明真实并发。

清单属于调用它的 Agent 会话。成功调用将完整快照写入 todo/write 事件，界面读取 todos projection；新一轮 turn/start 清空当前投影。模型看到的工具结果是计数文本，完整清单仍在调用参数和日志里。投影清空不等于删除历史，摘要也不能自动代替持久状态。

单会话所有权下，全量替换减少了逐项 ID 管理，但仍有最后写入覆盖先前更新的语义。多个 Worker 共用任务板时，需要稳定 task ID、owner、依赖和并发提交规则，见本章 §8.13 与 §8.15。不能把单会话清单工具直接当成共享任务系统。

completed 是进度声明，应有交付物与验证结果支持。上下文压缩和恢复时，从持久状态重建未完成任务，不能只靠最近一条自然语言摘要。本节具体 API 来自 DeepSeek 实现；共享任务板与验证边界是手册综合建议。
