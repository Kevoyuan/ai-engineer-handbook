Loop vs Graph：局部自治循环 vs 显式编排拓扑 §8.X

不要把 Loop 和 Graph 当成两代互相替代的技术。Loop 是一个 Agent 在局部任务中的自治控制模式；Graph 是把多个工作单元、决策边界和恢复路径组织成显式拓扑。

FIG.8.X

先把单个 Loop 做到可控，再在结构边界出现时拆成 Graph

默认从最小可控循环开始。只有当协调复杂度要求显式拓扑时，才增加 Graph 的控制流复杂度。

LOOP

一个连贯目标内的局部自治

Goal → Observe → Reason / Plan → Act → Verify → Stop or iterate。适合共享上下文、单一权限边界、明确验证方式与显式停止条件。
GRAPH

跨边界工作的显式协调

Router → bounded work units → branch / join → checkpoint → validation → recovery。适合并行分支、不同上下文或权限域、可审计决策点与独立恢复。
START

Bounded Agent Loop

先让状态、停止条件、验证和失败恢复可控。
BOUNDARY

结构性边界出现

并行 · 不同权限 · 不同上下文 · branch / join · checkpoint / resume · failure isolation · human approval
SPLIT

把边界拆成显式 Graph 节点与边

只增加解决真实协调问题所需的控制流复杂度。
UPGRADE什么时候从 Loop 升级为 Graph
看结构信号，而不是看流行词：并行轨道；不同 context / memory / permission；显式 branch / join；checkpoint / resume；failure isolation；需要审计的控制点；高风险动作的人审边界。
NODEGraph Node 不等于 Agent Loop
节点可以是 deterministic function、retrieval step、tool execution、policy gate、human approval、sub-workflow，也可以是 agent loop。Graph 定义的是拓扑，不要求每个节点都自治。

CANONICAL RULE

Use the least control-flow complexity that still makes state, stopping conditions, permissions, and recovery explicit.

PITFALL

A graph does not repair a broken loop. 如果单个循环的状态、验证、停止条件或工具策略本身有问题，套上一层 Graph 只会得到更复杂、同样不可靠的系统。
