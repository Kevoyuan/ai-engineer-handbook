Production Monitoring：把真实流量变成下一轮工程输入 §9.15

进入真实流量后，Monitoring 的问题不再只是“某一次运行为什么失败”，而是如何从成百上千条 Trace 中系统性地发现模式、持续评估质量、把重要案例路由到人工审查或数据集，并让 Production Evidence 真正回到 Build 与 Test。

FIG.9.M1

ADLC 有两个尺度：Build ↔ Test 内环，Deploy → Monitor → Build 外环

上线不会结束测试工作。Trace、Dataset 与 Evaluator 会在生产阶段继续作为 Monitoring 的基础设施。

1 · INSIGHTS

Batch Trace Mining

批量摘要 Trace、聚类相似行为与 Failure Mode，再生成值得调查的模式。目标是缩小人工注意力范围，而不是让聚类结果自动充当 Root Cause。
2 · SCORE

Online Evaluation

对全部或选定子集的 Production Trace / Thread 持续运行 Evaluator，把 Groundedness、Policy、Task Success Proxy、Sentiment 等转成可追踪信号。
3 · ROUTE

Signal-to-Action Automation

用 Filter + Sampling + Action 把值得关注的案例送往 Annotation、Dataset Candidate、Incident / Webhook 或延长 Retention。分数只有连接到动作，Monitoring 才开始形成闭环。
FIG.9.M2 · INSIGHTS PATTERN

Insights Agent 的核心不是“看更多 Trace”，而是先压缩，再聚类，再形成可行动发现

这是一种生产级批量 Trace Analysis 模式。Cluster 是调查入口，不是自动 Root Cause。

STEP 1

Summarize Traces

把每条 Trace 压缩成一行：关键动作、路径与结果，降低后续分析的上下文成本。
STEP 2

Cluster Summaries

把相似 Usage Pattern、Tool Path 与 Failure Mode 聚在一起，让重复问题从单条 Trace 变成总体模式。
STEP 3

Generate Report

从 Cluster 生成发现、代表案例与候选工程动作，再回到原始 Trace 验证根因。
SOURCE-SPECIFIC SCALE

课程示例说明 LangSmith Insights Agent 当前一次可分析最多约 1,000 条 Trace。这个数字属于来源中的实现能力，不是 Production Monitoring 架构的通用上限；真实系统仍需按成本、隐私、时间窗口与分层采样设计 Batch。

Offline Eval 与 Online Eval：测试证据和生产信号不是一回事

维度Offline EvaluationOnline Evaluation
输入Versioned Dataset / Regression / Holdout真实 Production Trace / Thread，通常可按规则或比例采样
主要用途版本比较、Regression、Release Gate趋势、Drift、异常发现、Case Routing
控制程度环境、Dataset、Evaluator 与版本尽量固定，强调可重复真实分布持续变化，必须处理 Sampling Bias、Evaluator Drift、Privacy 与成本
输出含义受控测试证据需要进一步解释与路由的生产信号
WHY USER SENTIMENT

课程用 User Sentiment 作为 Thread-level Online Eval 示例，因为 NPS、问卷、点赞/点踩依赖用户主动反馈，容易出现 voluntary-response bias。对真实 Conversation 做统一 Judge 可以扩大覆盖，但仍需 Human Alignment、Judge Versioning 与 Privacy Review。

BOUNDARY

Online evaluation scales judgment; it does not eliminate evaluator uncertainty. Online Judge 仍要版本化、校准并抽样做人审；高风险动作不能因为某个实时分数“看起来不错”就绕过 Policy Gate。

Automation Contract：Filter + Sampling + Action

Component工程问题例子
Filter哪些 Trace / Thread 值得处理？low eval score · error · high risk · negative signal · metadata slice
Sampling命中后处理多少比例？控制 Judge 成本、人工队列负荷与正常流量 Spot-check 覆盖
Action命中后下一步是什么？annotation queue · dataset candidate · webhook / incident · retention

DATASET GOVERNANCE

Positive sentiment 不自动等于 Golden Example，Negative feedback 也不自动等于 Regression Case。Production Data 进入 Dataset 前仍要经过 Privacy Review、Deduplication、Expected Behavior、Root Cause、Adjudication 与 Split Assignment。

CANONICAL RULE
