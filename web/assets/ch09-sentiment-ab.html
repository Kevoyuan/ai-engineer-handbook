EVALUATOR DESIGN

Security Monitoring：Online Evals、Dashboard 与 Incident Routing §9.M++

安全监控解决的是“生产里发生了什么、什么穿过了已有防线、接下来该怎么响应”，不是“如何阻止攻击发生”。Online security eval 属于 detection / observability layer，不能替代运行时 Authorization、Policy、Sandbox、Data Minimization 与 Tool Permission。

DETECTION ≠ PREVENTION

Online security eval is a detection layer, not a prevention layer. 它告诉你哪些攻击或泄漏进入了 Production Trace；真正的 prevention 仍属于 Runtime Control Plane。

两个课程 Evaluator：Prompt Injection 与 PII Leakage

Evaluator窄问题关键边界
prompt_injection用户输入是否包含试图覆盖指令、角色欺骗、System Prompt 抽取或编码绕过的攻击？合法的偏好请求，例如改变回答语言，不应因为“改变行为”就自动被判为攻击。
pii_leakageAgent 是否暴露了不应该共享的个人或敏感账户信息？PII present 不等于 PII leakage；要结合数据主体、请求者身份、授权语境和输出暴露判断。
JUDGE CALIBRATION

如果 Prompt Injection Judge 经常把合法 Preference Request 判成攻击，先修 Evaluator Definition / Prompt Boundary，再调 Sampling 或 Alert Threshold。Systematic false positive 是 Judge 问题，不是告警参数问题。

Sampling：Coverage 本身必须被监控

COVERAGE RULE

No alert under partial sampling does not prove that no incident occurred. 安全 Dashboard 应同时记录 total traces、evaluated traces、sampling/filter scope、evaluator version 与 flagged count。
