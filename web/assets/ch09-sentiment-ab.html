User Sentiment 与 A/B Testing：从体验信号到版本证据 §9.M+

Latency 与 Error Rate 能告诉你系统是否“运行正常”，却不能证明用户是否满意。课程补充了两条生产闭环：用显式反馈 + Thread-level inferred sentiment 捕获体验问题，再用 prompt_version metadata 把修复版本和 Control 放在真实流量中比较。

FIG.9.M4 · EXPERIENCE SIGNALS

User Sentiment 需要两条信号：用户主动说什么，以及完整对话暗示了什么体验

EXPLICIT

Thumbs up / down → trace feedback

LangSmith 示例用 create_feedback，把 user_sentiment=1/0 绑定到 trace_id。Root trace 通常足够；若需要阶段归因，也可以绑定到 child run。
INFERRED

Thread → LLM judge → sentiment

显式反馈覆盖稀疏，因此课程用 Thread-based Online Eval 在整段对话 idle 后判断总体满意度。它适合用户满意度、主题和多轮体验，而不是只看单个 Trace。
维度Single-turn evaluatorThread-based evaluator
InputSingle traceFull conversation thread
Trigger新 Trace 到达Thread idle 后
适合safety · format · per-run checkstopic · user satisfaction · multi-turn experience
EVALUATOR DESIGN

课程重申三个 LLM-as-Judge 规则：一次只问一个窄问题；输出 Binary / Categorical，而不是模糊的 1–5 分；定期和 Human Labels 对齐。Sentiment 示例把 Neutral 归到 Positive，并提高最终 Human Message 的权重。

SOURCE-SPECIFIC SETTINGS

课程把 30–50% sampling、Gemini 2.5 Flash / GPT-4.1 nano、Human-and-AI-pairs message format 作为 LangSmith Sentiment Evaluator 的起始配置示例。这些是产品/课程建议，不是跨平台通用阈值。LangSmith Online Evaluator 命中的 Trace 还会进入 extended data retention，因此会影响 Trace pricing。

HANDBOOK GENERALIZATION

Monitoring finds the problem; versioned experiments test the fix. 把 experiment / prompt / agent / workflow version 作为一等 Metadata，才能让 Feedback、Eval、Latency、Error、Cost 与 Release Decision 对齐到同一个版本切片。
