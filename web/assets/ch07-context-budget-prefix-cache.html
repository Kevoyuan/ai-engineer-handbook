Context Budget：压缩、卸载与 Prefix Cache §7.B

Context 快满时，不只是删掉 Token，还要保住决策依据与可信证据，并计算前缀复用的机会成本。比较两条不同的信息流。

FIG.7.B1 · TWO CONTEXT STRATEGIES

两条路径：压缩视图，还是卸载原始证据？

两者并不互斥；最重要的是把 Model-visible View 与 Authoritative Record 分开。

A · COMPACTION

改写 Active Context View

历史中抽取阶段结论、决策理由和未完成事项。
STEP 1

Conversation + Tool History

原始历史先保存到受控日志/快照。
STEP 2

Summarize + Validate Invariants

检查精确 ID、否定条件、约束和决策依据是否保留。
OUTPUT

Stable Prefix + Compact View

Token 占用降低；旧 conversation tail 的 cache 复用可能被重置。
B · OFFLOADING

外置大体积原始材料

Tool 输出、日志、文档不必每一轮都常驻 Prompt。
STEP 1

Large Tool Result / Artifact

保存原始输出与权限、版本、来源。
STEP 2

Artifact ID + Relevant Excerpt

只把指针与当下需要的证据送进 Context。
OUTPUT

Selective Re-read + Evidence

保留可追溯原始证据；未来读取需要额外 I/O 与 Token。
组合原则

Preserve decisions. Offload bulk. Stabilize prefix. Compact selectively.

FIG.7.B2 · CACHE BOUNDARY

摘要重写的是 Tail，不一定破坏前面的 Stable Prefix

BEFORE

压缩之前

[System + Tools] → [Turn 1 … 28] → [Turn 29]
AFTER

压缩之后

[System + Tools] → [New Summary] → [Turn 29]
LONGEST MATCHING PREFIX

稳定的 System / Tool Prefix 仍可能命中缓存；首次改变的位置之后，需要按新内容计算。最终是否命中取决于缓存断点、有效期、模型与服务商实现。

容易混淆

缓存命中降低 Prefill 计算，不代表缓存中的 Token 不再占用 Context Window。

FIG.7.B3 · DECISION AND MEASUREMENT

三问四招之后，检查是否真的更便宜、更可靠

01 · REUSE

未来还会用吗？

小而关键的状态固定保存；大证据按 ID 检索。
02 · EVIDENCE

决策依据还是流水账？

保留约束、否定条件、决策理由；卸载噪声。
03 · LAYOUT

稳定前缀还是动态尾部？

缓存真正稳定的部分；用户修正和授权变化必须更新。
EVALUATE

Task success + evidence fidelity + cached / uncached / write tokens + TTFT + total cost per successful task
