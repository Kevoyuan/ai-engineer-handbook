Coding Agent Engineering：从写代码转向定义、指挥与验证 §8.Y

Coding Agent 并没有消除软件工程流程，而是重新分配工程师的注意力：更少时间花在手写代码，更多时间花在决定做什么、设计架构、写清 Spec、校准 Agent 自主权、验证结果，以及把反馈带回前面的阶段。它们也可以承担数据分析、系统操作等非代码执行任务，因此真正需要治理的是整个 execution loop，而不只是 code generation。

FIG.8.Y

Coding Agent 工作流仍然是软件工程，只是执行者与注意力分布发生变化

Planning → Execution → Deployment & Monitoring 不是一次性流水线。验证或监控失败时，应该返回更早的阶段修正 Spec、架构、上下文或执行计划。

1 · PLAN

研究、理解代码库、写 Spec、拆计划

先明确需求、技术设计、架构、约束与验收标准，再审视关键假设、安全风险与是否过度设计。Greenfield 原型可以轻量；复杂 Brownfield 系统需要更严格的规划与验证。
2 · EXECUTE

构建、测试、验证，并校准自主权

决定哪些步骤需要高频人机往返，哪些可以委托成较大工作块；同时管理上下文、权限、并行 Agent 与人的注意力预算。
3 · DEPLOY / OBSERVE

通过 Gate 上线，再用证据驱动下一轮

使用 CI/CD 与必要的人审 Gate 部署；让 Agent 协助观察日志、发现问题、提出修复，但高风险副作用仍需要明确权限、验证与回滚边界。
ITERATIVE, NOT LINEAR

Verification 失败不只是“再生成一次代码”。它可能意味着 Spec 不清、架构假设错误、上下文过期、任务拆分不合理或验证器本身不够好。Monitoring 暴露的问题同样可能要求回到 Planning，而不是只在生产环境里打补丁。

五项核心能力：真正的稀缺资源是工程判断

能力工程师真正要决定什么薄弱时的典型失败
Directing the workflow规划多深、何时开始执行、何时回退、何时保留 Human Ownership；如何选择架构、写 planning artifacts / Spec，并在速度、成本、技术风险与人工投入之间权衡。Agent 很快地把错误问题做完，或者在没有验收标准的情况下持续漂移。
Enabling agent autonomy每个阶段需要多少自主权；什么时候交互式盯紧，什么时候委托大块工作或 bounded loop，什么时候并行多个 Agent，以及如何管理 Context、权限、Gate 与 Blast Radius。把“自主运行时间长”误当成熟度，导致错误更快扩散、上下文失真或高风险动作失控。
Reviewing the work什么证据能证明完成：自动测试、行为与功能验证、截图或 Artifact、Eval Set、LLM-as-judge、Agentic Code Review、安全/架构审计，以及哪些关键点仍需要人工判断。Agent 自己宣布完成就被当成完成，或者测试只验证实现细节而没有验证真实目标。
Customizing the agent and its environment如何用 Skills、Plugins、MCP、Hooks 与项目级说明文件提供工具和 Standing Context；如何跨 Session 保存必要状态、沉淀复盘，并清理过时能力与 Agent-generated debt。每个 Session 都重新解释项目，Agent 频繁丢背景，工具权限过宽，旧 Skill 与新模型能力互相冲突。
Coding agent foundations理解 Agent 如何搜索代码、检索上下文、使用 Context Window、调用工具与 Subagent，以及 Harness 如何约束模型行为与上下文成本。看不出 Agent 为什么过度设计、遗漏约束、提前停止或在错误上下文里继续自信执行。
AUTONOMY自主权是阶段级控制变量，不是成熟度徽章
高自主权适合可验证、可回滚、Blast Radius 小的工作；高风险规划、权限变更、生产副作用和不可逆动作应保留更强的人类 Gate。
CONTEXTContext 是工程基础设施，不是一次性 Prompt
项目约束、架构假设、代码风格、数据访问模式和当前 Spec 应有稳定、可维护的载体。需求中途变化时，必须更新 Agent 实际读取的 Context，而不是只在人的脑中更新。
CANONICAL RULE

A coding agent is an execution component inside a human-directed, testable, permissioned engineering loop.

CANONICAL RULE

Coding agents lower the cost of implementation; they raise the value of specification, verification, and engineering judgment.

PITFALL

Long-running autonomy is not a quality metric. 真正重要的是：目标是否清晰、Context 是否正确、权限是否受控、Verification 是否可信，以及工程师是否知道什么时候介入、回退或停止。
