Capability Architecture：Skill、Workflow、MCP 与 Tool 各自在哪一层 §6.A

这一章不只是“如何选 Skill”。生产系统还要区分能力契约、控制流程、协议接入和真实副作用执行；否则很容易把 Skill、MCP、Function Calling 和 Tool 混成同一层。

FIG.6.A1 · CAPABILITY ARCHITECTURE

从业务意图到真实执行：五层能力栈

上层决定“应该做什么”，下层负责“通过什么协议、由谁真正执行”；授权与验证贯穿边界。

LAYER 1

Business Goal / User Intent

目标、风险、当前状态、用户权限决定需要哪类能力。
LAYER 2

Skill Contract / Capability Registry

when_to_use · when_not_to_use · inputs/outputs · permission · risk · owner · version
LAYER 3

Workflow / State Machine / Policy Gate

决定执行顺序、缺失输入、审批、重试、停止和恢复；Skill 不等于一个裸 Tool Call。
LAYER 4

MCP / Function Calling / API Interface

负责 capability exposure、schema、discovery、transport 或 structured action proposal；它们不是最终业务授权。
LAYER 5

Host Execution → Tool / API / DB / Service

Host 做 schema validation、authorization、idempotency、timeout、logging，并承担真实副作用。
边界原则

Protocol exposes capabilities; Skill defines reusable task procedure; Workflow controls execution; Host owns authority and side effects.
