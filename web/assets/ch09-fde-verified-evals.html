FDE 评估面试：从 Golden Set 到 Agent Release Gate §9.FDE

四道高价值问题：如何验证 RAG 可上线、如何避免测试集泄漏、如何评价 Agent 的执行轨迹，以及如何用 Eval 阻止回归。

SOURCE BOUNDARY

以下是根据 FDE 网站公开考点独立撰写的问题与答案，不是付费题目的官方答案。产品细节以链接的官方文档为准；设计建议属于 Handbook 综合判断。

Q4 · 怎样评估 RAG 才能让客户放心上线？

分开衡量 Retriever 与 Generator，再加入授权、安全和运行指标。正确检索不保证正确回答；流畅回答也不证明有证据。

测试层指标 / 证据
Retrieval授权证据 Recall@k、MRR、Freshness
GenerationFaithfulness、Relevance、拒答是否正确
Security跨租户泄漏、越权工具调用
Productionp95 Latency、Timeout、Cost / Success
核心判断

只对必须基于检索证据回答的任务，Recall@k 才能合理限制下游 grounded success；这不是所有 LLM 输出的普遍数学上界。

Q5 · Golden Dataset 怎么建立？为什么 95% Pilot 可能只有 70% Production？

按真实流量中任务、语言、风险、文档、租户分层采样，建立人工确认的正确答案与证据；Development / Sealed Holdout / Stress Regression 三类样本用途分开。用独立新样本与固定桥接集区分版本提升与分布漂移。

95%→70% 并不能直接证明模型退化：还要排查真实样本构成、索引延迟、OCR、权限、模型版本与评估器变化。反复看 holdout 并针对它调参会污染独立验收。

Q6 · Agent 输出正确，是否就代表执行正确？

不一定。评估有无越权工具、危险参数、无意义循环、预算超限、未经批准的副作用。对必须经过审批的场景验证节点约束，而非强行要求所有合法执行拥有完全相同的工具顺序。

Input + approved identity
 → tool name / args / policy decision
 → tool outcome / state transition
 → artifact checks / final answer
 → outcome + risk + cost evaluator

Q7 · 如何把 Eval 变成能挡住坏版本的 CI Gate？

版本化 prompt、模型、检索器、数据集、grader 和基准分数。先跑 deterministic policy gates，再比较离线质量的关键 slices；严重越权始终阻断。通过后用 Shadow/Canary 观察线上，并保持回滚能力。

自动关卡何时阻断
Policy gate任何测试中的越权读取或危险调用
Golden set关键人群/任务出现不可接受退化
Judge audit评估器与人工标签偏差没有校准
Release telemetryCanary 错误率、p95 或成本超出约定预算
核心判断

LLM-as-a-Judge 可扩展语义评分，但不能代替确定性权限检查；官方工具支持 Offline/Online 和 Code/LLM 评估，阈值必须根据客户风险自行定义。
