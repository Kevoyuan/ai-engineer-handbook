Observability → Durable Evals：把一次失败变成可重复工程资产 §9.Y

传统程序的关键决策主要写在代码里；Agent 的部分决策由模型在运行时产生。因此调试不能只看异常栈，还要重建一次执行真正发生了什么：输入了什么、选了什么工具、参数是什么、返回了什么、经历了哪些状态、花了多少时间和成本，以及最终为什么通过或失败。

FIG.9.Y

Trace 解释一次运行；Thread 解释跨轮行为

可观测性记录模型可见消息、结构化决策、工具调用、结果与状态；它不要求、也不应依赖隐藏 Chain-of-Thought。

TRACE

单次 Agent Run 的可回放轨迹

prompt / visible messages · model / prompt / workflow version · structured decisions · tool + args · observation · validation · latency · tokens · cost
THREAD

多个 Trace 组成一次长期交互

用 session_id / thread_id / conversation_id 关联各轮 Trace，观察早期 Context 如何影响后续决策，以及问题从哪一轮开始积累。
BOUNDARY: Thread metadata 只负责把 Trace 归组，不等于对话持久化。真正的 Stateful Conversation 仍需要自己的 Message / State Store。
Eval Scope回答的问题典型检查
Step / Unit单个决策或组件是否正确？tool selection · SQL/schema check · retrieval query · parser output
Final / E2E从输入到最终结果，用户目标是否完成？correctness · relevance · groundedness · safety · task success
Trajectory即使答案正确，路径是否低效、重复或违反策略？step count · tool order · redundant calls · planning · recovery · loop rate
CANONICAL RULE

A correct final answer does not prove a reliable trajectory.

从手工 Debug 到 Durable Eval

FIG.9.Z

Build ↔ Test：失败先在 Trace 中被看见，再被固化为 Dataset + Evaluator

1 · OBSERVE

Run + Trace

先复现行为，找到真正失败步骤。
2 · SPECIFY

PRD → Scenario

从应该 / 不应该发生的行为定义测试场景。
3 · DATASET

Small, High-quality Cases

先覆盖 happy path、edge、OOD、adversarial 与历史失败，再逐步扩展。
4 · EVALUATE

Evaluator + Experiment

对每个版本重复运行，并比较 Slice、回归、成本与延迟。
5 · FEEDBACK

Bad Case → Regression

线上低分、负反馈与未覆盖输入经过归因和去重后回流。

Evaluator Routing：能确定就不要交给 Judge 猜

Evaluator什么时候用关键规则
Code-based可以写函数稳定判定：Schema、工具选择、关键字、SQL/数值、Latency、Cost、检索质量。确定性优先：快、便宜、易 Debug。
LLM-as-Judge语义标准很难写成规则，但人类能清晰判断。每个 Judge 单一窄目标；优先 binary / categorical；必须用人工样本持续 Alignment。
Pairwise绝对评分模糊，但比较 A 与 B 容易，例如 concise / professional / helpful。比较同一输入下两个版本；随机化 A/B 顺序，降低 position bias。
Human Review高风险、Judge 分歧、标准本身仍不稳定，或需要专家判断。Human 不是无限扩容方案；应把其裁决转化为 Rubric、Calibration Set 与 Regression Asset。
DATASET DESIGN

Dataset 应从 PRD 和真实 Failure Mode 派生，而不是为了凑数量。每个 Example 至少有 inputs；按需要加入 reference outputs 与 metadata。Reference 只给 Evaluator，不应泄漏给被测 Agent。

EXPERIMENT

Experiment = Target Agent × Dataset × Evaluators。大批量任务应控制并发；测试可以进入 CI/CD。框架 API 只是实现方式，真正稳定的是 Dataset Version、Evaluator Version、Agent Version 与可比较的结果。

LANGSMITH · IMPLEMENTATION EXAMPLE

LangSmith 可以通过 LangChain / LangGraph / Agent SDK 等集成自动采集 Trace，也可以对模型 Client 使用 wrapper，并用 traceable 装饰 Agent / Tool 函数。跨轮 Trace 可通过 session_id、thread_id 或 conversation_id 归组。离线实验可用 evaluate / aevaluate，测试也可接入 pytest。这里把这些视为 Observability / Eval 原则的一个实现，而不是架构本身。

PITFALL

Do not treat the trace viewer as the evaluation system. Trace 让问题可见；Dataset + Evaluator + Experiment 才让问题在未来版本中可重复检查。
