Cost per Successful Task：优化任务成本，而不是单次模型价格 §9.X

模型更便宜，不代表任务更便宜。弱模型如果带来更多重试、更多轮次、更多检索和更长上下文，总 Token 消耗可能上升，最终把单任务成本推高。

FIG.9.X

任务成本由 Token 量和混合单价共同决定

VOLUME

Total tokens consumed

检索、读文件、推理、重试、长上下文和额外轮次都会增加 Token 量。
RATE

Blended price per token

通过 model-family routing 与 model-tier routing，让常规步骤使用便宜模型，把强模型留给真正困难的少数步骤。
OUTCOME

Cost per successful task

最终指标应把成本与任务成功率放在一起看，而不是只看 Cost/query 或某个模型的标价。
INTERACTIVE · TASK ECONOMICS

为什么“更便宜的模型”可能产生更贵的任务？

调节 Token、混合单价、平均尝试次数与成功率，观察 Cost / attempt、Cost / task 与 Cost / successful task 如何分离。该模型只用于解释工程关系，不包含工具、GPU、人工审核等非 Token 成本。

读法：降低模型单价只有在不显著增加 Token、重试或失败率时才真正降低任务经济成本。生产系统应同时追踪成功率、总 Token、重试率、延迟与非 Token 成本。

CANONICAL RULE

Optimize cost per successful task, not price per model call.
