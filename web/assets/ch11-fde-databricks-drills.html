Q17 · AUTO CDC 和 MERGE 在乱序事件中怎么选？

Lakeflow 的 AUTO CDC 基于 SEQUENCE BY 排序，支持 Type 1/2 与 delete；通常优先用它处理满足约束的 CDC 流。自定义 MERGE 需要自己负责顺序、幂等、删除和历史。不能把两个独立来源的 version 任意互相比较。

CREATE OR REFRESH STREAMING TABLE order_status_history;
CREATE FLOW apply_order_cdc AS AUTO CDC INTO order_status_history
FROM stream(ops.silver.order_changes)
KEYS (tenant_id, order_id)
APPLY AS DELETE WHEN operation = 'DELETE'
SEQUENCE BY source_sequence
COLUMNS * EXCEPT (operation, source_sequence)
STORED AS SCD TYPE 2;
工程边界

这是有前提的 Lakeflow Pipeline 教学 SQL；需要合法源表、支持的 Runtime/Edition 和每个主键有效的排序键，不是本地 Spark SQL 命令。

Q18 · Delta CDF 能保证 30 天历史回放吗？

不能。CDF 要先启用，只包含启用后的变更且受到保留窗口限制。历史快照的切点、后续 source offset、归档策略和重放后的业务对账都需要定义。

Q20 · Watermark 会自动删除所有旧数据吗？

不会。它表示对事件时间迟到数据的容忍界限，在特定 Stateful Operator 下帮助清理旧状态；不会替代 Checkpoint，也不保证所有迟到事件都被处理。阈值应根据真实延迟分布和损失风险制定。

Q21 · SQL 跑得快但结果错，怎么分析？

MAX(event_time) 只能求最大时间，不能保证得到正确订单状态。检查来源权限、Source Version、Tombstone、时间语义、SCD2 Point-in-Time Join 和 Join Cardinality。

Q22 · Unity Catalog Row Filters 是否已足够保证 Text-to-SQL 安全？

不够。还需要身份可信、对象级 GRANT、SQL 限制、行列权限、审计和结果限制。ABAC 可在更高层级集中应用受控标签规则，但有计算版本和冲突限制；不要假设用共享服务账号查询会自动使用最终用户身份。

Q23 · “迟交率”应该让 LLM 自动定义吗？

不能。业务负责人必须确认分子、分母、时区、取消订单处理和记录版本。用 Metric View/Semantic Contract 统一定义，再用 Golden SQL Case 对比，避免同一概念在 Dashboard 和 Agent 中计算不同。
