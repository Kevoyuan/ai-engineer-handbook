Agent Architecture Selection：Pattern，不是七档成熟度 §8.AS

Single Agent、ReAct、Plan & Execute、Multi-Agent、Route + Skill、Shared State 与 Graph Workflow 不是同一维度的互斥架构。生产系统通常组合它们，真正的选型依据是控制流、状态、权限、恢复、成本与延迟。

FIG.8.AS1 · AGENT ARCHITECTURE PATTERN SPACE

“七种架构”其实分属五个控制维度

不要问“我属于哪一档”，而要问“我的系统在哪些维度需要更强控制”。

ACTORS

Single Agent ↔ Multi-Agent

决定需要几个独立决策主体，以及是否存在真实的 Context、权限、工具、评估或并行边界。
DECISION

ReAct ↔ Plan & Execute

局部一步一决策，还是先做全局分解再执行、验证与重新规划。
CAPABILITY

Router + Skill

当能力集合可枚举、边界可描述、路由可评估时，把开放推理压缩成候选能力选择。
STATE

Shared State / Blackboard-like

多个 Worker 围绕共享工作对象协作，需要 typed state、ownership、merge/reducer、version 与 conflict policy。
CONTROL

Graph / Durable Workflow

当 branch、join、loop、checkpoint、resume、HITL、恢复与审计路径本身就是业务契约时，把拓扑显式化。
组合原则

Agent architectures are composable control patterns, not a maturity ladder.

FIG.8.AS2 · FAILURE-DRIVEN SELECTION

从真实失败模式反推控制 Pattern

只有当新的控制结构解决了已观察到的问题，它的复杂度才值得。

失败 / 需求 优先考虑 为什么
Small tool set · short horizonBounded Single Agent最小协调开销
Next action depends on fresh observationReAct-style loop逐步动态决策
Long task · global decompositionPlan & Execute分离规划与执行，并允许 re-plan
Large known capability catalogRouter + Skill可检索、可授权、可评估
Context / permission isolationMulti-Agent / Subgraph真实 operational boundary
Shared work state conflictsTyped Shared State明确 ownership、reducer 和 version
Branch / join / loop / HITLGraph Workflow控制拓扑成为业务规则
Crash must not restart the whole jobDurable Workflow Runtime恢复保证优先
框架 ≠ Pattern

LangGraph 是 stateful Agent orchestration；Temporal 强调 durable workflow execution；Prefect 是 workflow orchestration；n8n 是 workflow automation。选择 runtime 时看 execution guarantee 和 integration model，而不是都贴上“Agent Graph”标签。
