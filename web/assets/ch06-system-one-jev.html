System-One Decision Models：把 Jev 放进 Routing Cascade §6.C

Jev 更适合被理解为一种 typed probabilistic decision layer，而不是更小的聊天模型。它处理答案空间预先定义的 Noul / Choice / Score 决策；开放式生成、复杂规划和多步推理继续交给 System-Two LLM。

FIG.6.C1 · SYSTEM-ONE + SYSTEM-TWO

快决策负责封闭判断，慢推理负责开放任务

这不是模型代际替换，而是把不同任务形状放进不同执行层。

STATE

User / Program State

自然语言、结构化业务状态、Agent trace 或其他待判断输入。
SYSTEM ONE

Typed Probabilistic Decisions

Noul · Choice · Score
输出预定义类型、概率与 confidence，适合 classify / route / score / gate。
GATE

Confidence + Policy

高置信、低风险可以直接分支；低置信、缺信息或高风险进入 clarify / review / escalation。
SYSTEM TWO

General LLM Planner

开放式生成、组合意图、多步骤规划、代码与报告等不能提前枚举答案空间的任务。
CONTROL

Authorization · Validation · Host

无论哪种模型作出决策，真实副作用仍由权限、schema、审批、验证和 Host 控制。
架构原则

Closed decision → typed probabilistic fast path. Open reasoning → general planner.

三种 primitive 对应三种可编程决策形状

Primitive 输出 适合
Noulyes / no 概率risk gate · condition · escalation

关键边界

Type-safe ≠ semantically correct. 输出不会跑出 schema，不代表业务判断一定正确；confidence calibration、fallback、slice eval 与高风险人工复核仍然需要。

维度 System-One / Jev-shaped General LLM / System-Two-shaped
答案空间预定义、typed开放文本 / 代码 / 计划
核心动作classify · choose · score · gategenerate · reason · synthesize · plan
主要优势直接进入代码分支；显式概率 / confidence表达能力强；能处理开放和组合任务
主要限制无法自由生成任意内容延迟 / 成本更高，输出自由度增加验证负担

截至 2026-09-23，Jev 仍为 TypeSafe early access。其速度与成本优势来自 TypeSafe 公布的 System-One-shaped workflow 评测，应视为 vendor benchmark，而不是通用 SLA。生产选型仍应在自己的数据上测 accuracy、calibration、P50/P95、cost/success 与 downstream task success。
