System-One Decision Models：把 Jev 放进 Routing Cascade §6.C

Jev 更适合被理解为一种 typed probabilistic decision layer，而不是更小的聊天模型。它处理答案空间预先定义的 Noul / Choice / Score 决策；开放式生成、复杂规划和多步推理继续交给 System-Two LLM。

FIG.6.C1 · SYSTEM-ONE + SYSTEM-TWO

快决策负责封闭判断，慢推理负责开放任务

这不是模型代际替换，而是把不同任务形状放进不同执行层。

STATE

User / Program State

自然语言、结构化业务状态、Agent trace 或其他待判断输入。
SYSTEM ONE

Typed Probabilistic Decisions

Noul · Choice · Score
输出预定义类型、概率与 confidence，适合 classify / route / score / gate。
GATE

Confidence + Policy

高置信、低风险可以直接分支；低置信、缺信息或高风险进入 clarify / review / escalation。
SYSTEM TWO

General LLM Planner

开放式生成、组合意图、多步骤规划、代码与报告等不能提前枚举答案空间的任务。
CONTROL

Authorization · Validation · Host

无论哪种模型作出决策，真实副作用仍由权限、schema、审批、验证和 Host 控制。
架构原则

Closed decision → typed probabilistic fast path. Open reasoning → general planner.

FIG.6.C3 · TASK-SHAPE SELECTION

先问能不能用代码，再问是不是 Decision Model

有限答案空间并不自动意味着需要模型。真正的 Jev-shaped task 是“预定义输出 + 模糊语义判断”。

DETERMINISTIC

Code

规则可以可靠计算：金额阈值、权限、allowlist、预算上限、状态机合法转移。
FUZZY + BOUNDED

Decision Model

答案集合已知，但边界需要语义判断：风险、意图、相关性、质量、是否继续。
OPEN OUTPUT

Generative LLM

输出无法预先枚举：代码、报告、解释、研究、规划、组合式推理。
三层分工

Deterministic truth → code. Fuzzy bounded judgment → decision model. Open-ended work → generative LLM.

并行边界

对同一 state 的独立判断可以 batch / parallelize；如果 B 依赖 A 生成出的新 evidence，workflow 仍必须保留 causal order。Parallel sampling 减少不必要的串行生成，不消除真实数据依赖。

FIG.6.C4 · Jev vs. Generative LLMs

BEFORE

生成式模型包办所有任务

Single LLM → Plan · Write code · Route model · Research · Score result · Tool approval? · Task complete? · Progress?
AFTER

按职责拆分生成、决策与执行

Generative Model · 编码、规划、研究、开放生成
Jev · 模型路由、风险检查、进度、完成判断；类型化概率
Runtime · 权限、预算上限、允许列表、执行或拦截

职责分离不代表模型判断自动可靠；执行边界仍由 Runtime 掌握。

Agent Loop：五个有边界的决策检查点

AI Engineering 2026-09-23 的 Jev 文章以修复代码 Bug 的 Agent 为例：开放式工作交给主 LLM，执行前后和每一轮循环中的模糊但封闭判断可交给 Decision Model，最终权限与执行权始终留在 Runtime。

检查点 模型辅助判断 代码控制 / 证据边界
01 · 路由下一步选哪个模型、哪些工具相关？能力允许列表、模型与成本预算
02 · 执行前完整命令是否有风险、是否需要审批？校验参数、权限、sandbox、人工批准；分数不能授权
03 · 执行后结果质量是否足够继续？先核验 exit code、测试和产物，再做语义判断
04 · 循环是否陷入重复 search / open？是否有进展？硬性最大轮数、超时、重试与花费上限
05 · 验收目标完成了吗、回答有依据吗？真实测试结果、diff、验收条件，不能只信 Agent 自评

例如 rm -rf ./build 的风险依赖上下文，但能否执行必须依赖真实权限和路径检查。让通用 LLM 返回 JSON 仍是受约束生成；Jev 的产品定位是直接返回预定义的类型化概率判断。两者都不能把类型正确等同于业务正确。

Jev confidence 的含义

Choice confidence 是候选分布相对均匀分布的归一化集中度，并非正确率：confidence = (p_max − 1/n) / (1 − 1/n)。三个候选中 p_max = 0.6 时 confidence = 0.4。Score 还考虑等级距离，Noul 没有单独 confidence；概率校准仍需在本地留出集分片验证。
