Reliability Control Plane：把 Runtime、Eval、Release 与 Monitoring 放进同一张图 §9.A

本章的 Dataset、Evaluator、Trace、Release Gate、Monitoring 和 Cost 不是六套独立机制。它们共同构成 Runtime 外围的控制面：在执行前约束，在执行中观测，在执行后判定，并把生产证据送回下一轮 Build/Test。

FIG.9.A1 · RELIABILITY CONTROL PLANE

Runtime 是数据面；Reliability / Eval / Observability 是控制面

不要把“跑 Agent”和“证明 Agent 可以安全上线”混成同一条流水线。

DATA PLANE · RUNTIME

Request → Agent / Workflow → Model / Tool → Validation → Response / Action

这里发生真实用户请求、工具调用、状态变化和副作用。
BEFORE / DURING

Policy + Validation

schema · permission · safety · HITL · retry/fallback boundary
DURING

Observability

trace · thread · state · tool · token · latency · cost · version metadata
AFTER

Evaluation

dataset · code evaluator · LLM judge · pairwise · human · trajectory / E2E
RELEASE CONTROL

Experiment / Regression → Release Gate → Shadow / Canary → Promote or Rollback

发布决策同时看 Task Success、风险违规、P95、Cost / Success 与关键 Slice；不是只看一个平均分。
PRODUCTION LEARNING LOOP

Monitor → Detect Signal → Inspect Trace → Root Cause → Curate Dataset / Evaluator → Fix → Re-evaluate

Monitoring 只有把生产行为变成可复现的测试证据，才真正闭环。
架构原则

Runtime produces behavior. The control plane constrains, measures, judges, releases, and learns from that behavior.
