LangChain vs LangGraph：抽象层，而不是二选一 §8.Y

“LangChain 做链，LangGraph 做复杂 Agent”只能算历史直觉。当前 LangChain 更偏高层 Agent / Application Framework 与组件生态；LangGraph 更偏低层 Stateful Orchestration Runtime。更关键的是，LangChain 的 create_agent() 本身建立在 LangGraph 上。

FIG.8.Y0 · MODEL CALL VS APPLICATION STATE

单次模型调用不会自动变成可恢复的工作流状态

消息历史回答“之前发生了什么”；Workflow State 还必须回答“执行现在在哪里、接下来允许做什么”。

MODEL CALL

Input → Model → Output

模型只基于当前可见输入计算输出；持久化业务状态需要应用或运行时显式管理。
WORKFLOW STATE

Task · Tool Results · Retry · Approval · Next Step

复杂 Agent 需要保存任务进度、中间结果、失败状态、审批状态和下一步，而不只是聊天记录。
LANGGRAPH

State → Node → Patch → Route → Checkpoint

把执行状态和转移显式化，使 branch、loop、retry、interrupt / resume 与 HITL 成为可检查的控制流。
FIG.8.Y1 · ABSTRACTION STACK

先选最高层、但仍能显式表达关键控制边界的抽象

LANGCHAIN

Models · Tools · Retrievers · Runnables · Middleware · create_agent()

标准接口、第三方集成、可组合组件和预构建 Agent 架构。适合快速获得常见能力，而不是重复造基础组件。
LANGGRAPH

State · Nodes · Reducers · Edges · Scheduler · Checkpoints

当 orchestration 本身成为业务逻辑：自定义 State、branch/join、循环、恢复、持久化、HITL、长期运行任务。
COMMON PATTERN

LangChain components inside LangGraph nodes

生产里最常见的不是二选一，而是用 LangChain 提供能力，用 LangGraph 显式组织控制流。

CANONICAL

LangChain and LangGraph are abstraction layers, not mutually exclusive competitors. 当前 LangChain Agent 建立在 LangGraph 上；标准架构优先用 LangChain，当 orchestration 本身成为应用逻辑时再下沉到 LangGraph。

CHECKPOINT BOUNDARY

Checkpoint 保存的是执行 State Snapshot，不是自动事务。外部数据库、支付、邮件等 Side Effect 仍需要 idempotency / reconciliation；恢复语义发生在 checkpoint / super-step 边界，而不是任意程序指令位置。
