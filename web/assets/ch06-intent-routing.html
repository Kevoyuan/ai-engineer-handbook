Intent Routing：不要让一种机制吃掉全部流量 §6.B

生产级意图识别不是“规则还是大模型”的二选一，而是按置信度、任务复杂度、风险与成本逐层升级。便宜且确定的请求应尽早退出；只有真正模糊或组合式任务才进入高成本 planner。

FIG.6.B1 · COST-AWARE ROUTING CASCADE

从确定性 Fast Path 到结构化 Planner

每一层都必须有置信度出口；不确定性进入下一层，而不是被强行分类。

INPUT

User Turn + State

先更新 current task、active entity、filled slots、corrections 与 topic-scoped state。
FAST PATH

Deterministic Gate

Exact mapping · regex · FSM · typed command。只接稳定、低歧义、高置信边界。
CONTEXT

State-aware Router

Referent resolution · continuation/topic shift · lightweight classifier / semantic match · confidence gate。
ESCALATE

Structured LLM Planner

处理 ambiguous / compositional / multi-step 请求；输出 typed capability/tool proposal，而不是只猜一个 Intent label。
CONTROL

Permission · Risk · Input Gate → Host

Capability match 之后仍需 authorization、schema、approval、idempotency 与 result validation；Host 才拥有真实执行权。
升级原则

Escalate by uncertainty, task complexity, and risk—not by a fixed technology ladder.

FIG.6.B2 · ROUTING DECISION BOUNDARIES

Intent、Capability 与 Authorization 是三个不同决策

1

Intent Understanding

用户想完成什么？当前 turn 是否依赖旧 state / entity / slot？
2

Capability Routing

哪个 Skill / Workflow / Tool 组合能够完成该目标？允许 DIRECT、MULTI、CLARIFY、NO_MATCH。
3

Authorization / Execution

用户现在是否被允许调用它？风险是否要求审批？参数是否完整？Host 是否可以安全执行？
