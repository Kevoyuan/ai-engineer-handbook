Intent Routing：不要让一种机制吃掉全部流量 §6.B

生产级意图识别不是“规则还是大模型”的二选一，而是按置信度、任务复杂度、风险与成本逐层升级。便宜且确定的请求应尽早退出；只有真正模糊或组合式任务才进入高成本 planner。

升级原则

Escalate by uncertainty, task complexity, and risk—not by a fixed technology ladder.

越往下流量越少，歧义、复杂度和单请求成本越高

漏斗不是为了强行追求某个流量比例，而是让简单稳定的问题尽早退出，把昂贵推理预算留给真正需要它的长尾请求。

ANTI-PATTERN

Rule Black Hole

LLM Front Door

路由机制与退出条件

下面是机制选择表；实际顺序由流量、任务状态和风险决定。关键词命中也要检查否定、引用和实体，例如“不要退款，只查订单”。

机制适用边界退出条件
规则 / typed action明确、稳定且上下文一致冲突或缺少实体 → context router
向量示例路由与已标注意图相似；含正例和 hard negatives按 Route 聚合；低相似度或小 margin → clarify / no match
封闭决策模型候选答案可预定义，例如 Jev Choice校准 gate 不通过 → review / escalate
LLM / planner模糊、跨域或多步任务输出 typed plan；执行前仍检查权限和输入
反问 / no match缺少用户信息、意图冲突或超范围问“申请退款还是查询订单？”；范围外明确 no match

分数需要校准

自报 confidence、向量相似度和 token logprobs 都不能直接当成业务正确概率。logprobs 是否可用取决于 model、endpoint 和 reasoning mode；多 token 标签要比较完整序列，不能只取首 token 或截断候选。

隔离示例库、校准集与测试集，按模板、用户或时间去重划分。检索 few-shot 示例的收益要测每类 precision / recall、校准和自动处理覆盖率；71%→93% 未获可复现来源支持。

OpenAI Agents SDK handoff

Python SDK 的 Agent(..., handoffs=[refund_agent, order_agent]) 将转交目标暴露为模型可选工具。triage agent 是分诊角色，不是特殊类。默认 Refund Agent 对应 transfer_to_refund_agent；默认描述是 Handoff to the {agent.name} agent to handle the request. 后接 handoff_description，且可 override。

handoff 转移当前分支控制权；agent as tool 让 manager 保留最终回复责任。清晰描述只是一个因素，工具包装仍需模型选择，不自动降低延迟。小候选集合可以直接路由，规模和混淆度增长时再引入检索。

默认传递历史，按数据边界筛选/脱敏。Python input_type 只约束转交 metadata，不替换接收 Agent 输入或动态选目的地；is_enabled 控制候选可见性。依赖解析参数的授权应在 on_handoff 开始检查，拒绝时抛出失败；Host Policy 始终保留执行权限边界。

多意图与有界恢复

同时要求多件事应按业务优先级、风险和依赖拆成计划；分不清意图才反问。超范围时返回 OUT_OF_SCOPE + reason + unresolved_goal，或配置 return handoff。Host 限制 handoff_count、总 turn / latency budget，检测相同 agent / goal / state 的无进展循环；耗尽后 clarify / escalate，不能换 Agent 绕过拒绝。

意图数量增长时沿用 soft hierarchy / Top-M domains；是否分层看召回、混淆、上下文成本和维护负担，20 个不是硬阈值。SDK、模型与数字的核验日期为 2026-10-03。
