Agent Sandbox：把执行能力限制在可证明的 Blast Radius 内 §10.S

Sandbox 不是 VM 的同义词，而是受控执行边界。真正需要同时约束 filesystem、network、process/syscall、resource、credential、lifecycle 与 audit；模型只负责提出动作，Host/Sandbox Policy 才拥有真实执行权。

FIG.10.S1 · SANDBOX CONTROL PLANE

Approval 控制意图，Sandbox 限制能力

把 Agent proposal、权限决策、运行时隔离、执行证据与验证串成一条可审计链。

01

Agent Proposal

run command · install package · write file · connect endpoint；模型表达意图，但没有直接宿主权限。
02

Permission / Risk Gate

根据 action、scope、tenant、risk、approval 与 policy 决定是否允许进入执行层。
03

Sandbox Scheduler

选择 image / template、writable roots、network policy、CPU / memory / disk / PID / timeout 与 secret strategy。
04

Isolated Runtime

OS sandbox / container / gVisor-like / microVM / constrained runtime 在技术层强制 filesystem、process 与 egress 边界。
05

Evidence + Validation

command、exit code、file diff、network、resource、policy decision 与 artifact validation 回写 Trace；失败可 kill / reset / rollback。
核心原则

The model proposes an action; the sandbox enforces the physical capability boundary.

选型变量

真实安全性还取决于 mounts、credentials、egress、host services、kernel/hypervisor patching、escape hatch、image provenance 与 runtime configuration。隔离技术名词本身不能替代 threat model。

Secret Rule

The safest secret in a sandbox is the secret that never enters it.

Benchmark Rule

启动时间与内存数字必须带 workload、hardware、snapshot/template、guest size 与 concurrency 条件；不要把 vendor benchmark 当成跨产品恒定事实。
