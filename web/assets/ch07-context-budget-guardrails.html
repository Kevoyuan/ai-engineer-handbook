上下文预算：滑动窗口反例与请求准入 · §7.13.3 / §7.13.7

滑动窗口不天然保住旧历史的前缀缓存：[System][A][B][C] → [System][B][C][D] 的首次变化在 System 后。B/C 顺序没变，也不是旧请求从开头延伸的相同前缀。System 是否能复用仍受服务商规则约束；这不同于引擎内部的 sliding-window attention / KV eviction。

摘要、外部记忆召回和 Rerank 都应按首次变化位置判断缓存边界。动态证据 suffix 改变时，前面的稳定指令可能仍可复用。用实际 cache read、未缓存输入与任务质量评测，不按操作名称猜命中率。

请求前检查：assembled_input_tokens + reserved_output_tokens + safety_margin ≤ model_context_limit。assembled_input_tokens 包含实际发送的 system、tools、历史、检索结果和摘要；已有工具结果不要重复计数。按具体模型/API 检查思考 token、隐藏封装及独立输入/输出限制，有条件时调用 token counting 接口。

下一轮工具结果或用户输入需要预留有界容量，或在装配前截断/卸载。75%～80% 不是通用预警标准，更不应等到 100% 才兜底；应在发送前拒绝或重组超预算输入，并为压缩操作本身预留空间。

安全裁剪应保留当前目标、精确 ID、否定约束和证据指针，并遵守 provider 的消息配对规则；不要留下无配对 tool result 或删掉仍在使用的 tool call。无法安全装配时暂停、缩小任务或请用户选择，不静默丢关键约束。这里是本手册工程建议，具体协议要求需单独检查。
