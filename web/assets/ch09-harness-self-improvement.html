Harness 自我改进：候选编辑与证据边界 · §9.21.21

只重试同一套指令会得到新样本，却可能保留原来的失败原因。Harness² 是 Google Research 的研究发布，保持模型权重固定，把执行设置变成可编辑的实验对象；它不是受官方支持的 Google 产品。

任务级递归：Propose 检查参考运行并提出编辑 → Probe 在同一任务、匹配条件下执行候选 → Compose 根据行为差异保留或组合编辑。选择过程不使用 ground-truth 反馈，因此行为改变本身不能证明答案正确；两次运行仍可能共享错误前提。

八个可编辑组件分四组：context construction（system prompt、guardrails、memory、skills）；tool interface（tool guidance、scripts）；delegation（subagents）；middleware（plugins）。这是框架的具体编辑面，不是所有 Harness 的统一分类。

Harnessing 级递归由 experience reflector 将被采纳的 Harness 与有证据支撑的 lessons 写入 persistent improvement harness，用于未来任务。应保留编辑为什么有效及何时适用，而不是直接搬用上一次最终配置。README 保存 adopted harnesses 和 reflection notes；原通讯稿提到的 EXPERIENCE.md 没有得到确认。

候选编辑必须经过既有晋升流程：OBSERVED → CANDIDATE → VALIDATED → SHADOW → ACTIVE。无标准答案的对比证据只支持候选选择，正确性和发布安全仍需独立验证。Agent 可以提议编辑、执行有授权的探测，但放宽自身 guardrail 或权限边界必须交给外部策略所有者批准。

k 是任务级递归预算：k=1 是一次 Propose–Probe–Compose；并行模式探测 k 个 general 与 k 个 domain-specific 候选，产出 k 个组合；串行模式连续迭代 k 步。每个 probe 都要实际执行，比较时应把 base、所有候选探测、judging 和 reflection 的实际成本计入每个已验证成功任务的成本。

评估边界：对比能证明变化，不能自证正确；README 明示 executor 网络访问不受限、Codex 关闭 sandbox，公开 benchmark 的答案与评分标准可能在线可得，评测前必须限制网络；任何涨分结论都要先检查污染风险。

作者自报：四种 model–harness 配置覆盖 GLM-5 与 Gemini 3.5 Flash，最高 WorkBuddy-Bench +11.5、JobBench +4.5、LAB partial pass rate +11.8 个百分点；未独立复现，不能推广为每个模型都能获益。judge、report 与 refinement 必须保持 benchmark、executor、subset、k、mode 和 seed 一致。

本手册综合建议：晋升编辑背后的证据与适用条件；把权限、预算和发布批准保留在 Host / Workflow；独立评测已验证成功率、失败切片、延迟和总成本。自我修改机制本身不授予 Agent 更多权限。
