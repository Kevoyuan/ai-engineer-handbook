数据与 SQL 工程

让数据在生产系统中保持正确、及时、可回溯、有权限边界。理解 CDC、Lakehouse、SQL、Spark 与 Text-to-SQL 的集成决策。

11.1 端到端数据路径：从源事件到可信 AI Context

FDE 不该只讨论 RAG 检索策略，还要确认：数据是谁提供的、更新有多快、何时可以查询、出了错是否能重放，以及租户权限在哪里执行。

Source DB / SaaS / events
    ↓ CDC / batch extract
Bronze · raw append + offsets
    ↓ schema / dedup / quarantine
Silver · verified, versioned entities
    ↓ contracts / temporal joins
Gold · governed customer views
    ├── SQL, BI and workflow queries
    ├── model features
    └── retrieval indexing → RAG
边界必须明确的约束常见失败
Capture事件序列、offset、delete漏更或重复
Normalize唯一键、schema、时区跨系统错配
Consumefreshness、租户、可追溯过期或越权读取
工程结论

实时 Agent + 错误的数据 = 快速出错。数据正确性、及时性与授权是不同的验证维度。

11.2 ETL / ELT / CDC：选最适合数据边界的路径

机制适用情况要验证的问题
ETL先清洗/限制敏感数据再入库前置逻辑能否重放？
ELT先安全留存原始数据，再在仓内转换原始数据访问是否隔离？
CDC增量变更与删除传播初始快照、顺序、offset 与 tombstone

Batch 与 Streaming 取决于消费者对事件可见延迟的目标，而不是“实时”是否听起来更先进。

11.3 Idempotency：允许消息重复，不允许业务结果重复

event(source, event_id, entity, version, operation)
 → durable raw log
 → validate + quarantine
 → dedup(source, event_id)
 → merge if version is newer
 → atomically commit sink and checkpoint

At-least-once delivery 不是异常，而是工程约束。必须明确谁生成稳定的幂等键、何时重试、如何处理 out-of-order 更新与删除，以及跨系统写入如何补偿。

11.4 Lakehouse / Delta：Bronze、Silver、Gold 各自负责什么

层职责不可误认为
Bronze可重放原始数据、provenance原始数据可信
Silver校验、去重、更新、实体标准化业务含义已经统一
Gold业务契约与消费者视图自动解决跨系统事务

Delta transaction log 提供表层面的快照和原子提交；它本身不能保证 HTTP、消息队列、其他数据库之间的 exactly-once 业务效果。

11.5 SQL Window 与 SCD2：保留时序真实性

WITH ranked AS (
  SELECT *, ROW_NUMBER() OVER (
    PARTITION BY tenant_id, entity_id
    ORDER BY source_version DESC, ingested_at DESC
  ) AS rn
  FROM normalized_events
)
SELECT * FROM ranked WHERE rn = 1;

最新记录查询必须定义版本比较、并列消解、删除语义。SCD Type 2 使用 effective_from / effective_to 维护历史快照；point-in-time join 避免训练时偷看未来。

11.7 Text-to-SQL：能执行 ≠ 有权限

User intent
 → approved semantic schema + identity
 → SQL candidate
 → parse / allowlisted operations
 → database RLS / scoped credentials
 → EXPLAIN / row and time budget
 → run / verify / return source freshness

LLM 生成一个 SELECT 不等于安全。权限应由数据库策略或可信服务执行；解析、只读角色、超时、成本预算及结果验证都是独立关卡。

11.8 订单状态错乱：用可复现的证据交付

客户发现订单在快递交接前显示“已签收”。第一步不是微调 LLM，而是核对来源事件时间、序列、重复、删除和最终状态定义；再用 golden timeline 验证事实还原。

验收指标意义
CDC lag p95变更到可查询的延迟
Duplicate-effect rate重复消息导致重复业务影响的比例
Reconciliation completeness源系统与目标结果可核对
Policy-leak tests跨租户请求无法取数
