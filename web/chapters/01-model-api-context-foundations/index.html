CHAPTER01

Model / API / Context 基础

模型基础不是背参数名，而是理解：输入怎样变成 Token、Token 怎样经过 Transformer、Context 怎样被预算、输出怎样被采样、什么时候该 RAG / Fine-tune / Cache，以及怎样验证一次模型变化没有破坏生产行为。

1.1 Generation：Prefill 与 Decode

Autoregressive LLM 不是一次生成整段答案，而是反复预测下一个 Token。在线推理要把 Prefill 与 Decode 分开看：前者处理输入前缀并建立上下文状态，后者逐 Token 生成并复用已有 KV。

FIG.1.1 · INFERENCE LIFECYCLE

从文本到下一个 Token

1 · TOKENIZE

Text → Token IDs

使用目标模型对应 tokenizer；Token 数决定上下文、成本与缓存身份。
2 · PREFILL

Input tokens → hidden state

输入批量处理，通常主导 TTFT 中的模型前缀计算。
3 · LOGITS

Vocabulary scores

输出层为候选 Token 产生 logits。
4 · SAMPLE

Temperature / Top-p

采样策略控制变化性，不提供真实性。
5 · DECODE

Next token → repeat

逐 Token 生成；输出越长，顺序 Decode 越多。
核心规则

Prefill and Decode are different performance regimes; diagnose them separately.

1.2 Transformer：理解 Q/K/V，而不是把 Attention 当数据库

Transformer 通过多层 Attention 与前馈变换构造上下文表征。Attention 的核心是 Q/K 的兼容度打分，再用归一化权重聚合 V；它描述网络内部依赖，不等于事实检索或验证。

Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V
架构信息可见性典型用途关键修正
Encoder-onlybidirectionalclassification · embedding · labeling更偏表征学习
Decoder-onlycausalopen-ended autoregressive generation主流生成架构之一，不是唯一生成架构
Encoder–Decoderencoder bidirectional + decoder causaltranslation · summarization · seq2seq同样可以生成

RoPE 通过位置相关旋转把相对位置信息带入 Attention，但不保证无限长度可靠外推；FlashAttention 通过 IO-aware tiling 避免在 HBM 中物化完整 N×N score matrix，改变的是精确 Attention 的实现效率，而不是语义定义。

1.3 Token 与 Context：字符是 UI 数量，Token 才是 Runtime 数量

Token 可能是单词、子词、字节片段、标点、空格敏感片段或代码片段；具体划分由 tokenizer 决定。因此不能把固定字符数/单词数换算规则当作工程事实。

FIG.1.2 · CONTEXT BUDGET

Context Window 是共享预算，不是 RAG 专属容量

INSTRUCTIONS

System / Developer

核心约束、角色与任务协议。
CAPABILITIES

Tool schemas / examples

工具定义与 few-shot 也占 Token。
EVIDENCE

History / Memory / RAG

历史、记忆与检索证据必须竞争同一预算。
RESERVE

Output / reasoning

必须为输出和必要的推理预算预留空间。
容量 ≠ 利用率

长 Context 能装下更多 Token，但相关证据是否被可靠利用仍是模型、长度、位置和 Prompt Layout 的经验问题。

当 Prompt + 文档超窗时，优先考虑 rerank、减少 top-k、去重、结构化 state、分解任务、压缩或 staged synthesis。Lost in the Middle 说明相关信息位置在某些长上下文任务中会影响性能，因此应做 position-sensitive eval，而不是机械地把重要内容永远放在两头。

1.4 Sampling：Temperature / Top-p 只控制变化性

机制控制什么不解决什么
Temperature分布 sharpness / randomness事实缺失、错误检索、权限、业务有效性、工具副作用
Top-p进入采样候选集的累计概率质量
常见误区

Temperature = 0 ≠ truth. 低温可以降低采样变化，但不能把错误知识、错误 Evidence 或错误 Tool Result 变成正确答案，也不保证跨后端/版本 bit-for-bit 一致。

1.5 Embeddings：Similarity 是候选生成，不是 Correctness

Embedding 把文本或对象映射到向量空间。Dot Product 同时受方向与向量 magnitude 影响；Cosine 会归一化 magnitude。若向量已经 L2-normalized，Dot Product 与 Cosine 可以产生相同 ranking——但这是具体 embedding family 的性质，不是所有向量模型的默认定律。

x · y = ||x|| ||y|| cos θ

cos(x,y) = (x · y) / (||x|| ||y||)

Dense retrieval 容易把主题相近但动作相反、版本不同、日期不同的内容放在一起。因此生产检索通常需要 Authorization / Metadata → Exact/BM25/Dense → Rerank → Evidence Validation。

1.6 Base、Instruct 与 Post-training

Base model 主要学习 next-token continuation；Instruct / aligned model 在预训练之后继续做行为适配。Post-training 可能包含 SFT、preference data、reward modeling、RL-based optimization、DPO 或安全训练，不应把 instruct 简化成“等于 RLHF”。

FIG.1.3 · POST-TRAINING PATHS

Preference optimization 不是单一路线

CLASSIC RLHF

SFT → Reward Model → PPO

奖励模型提供 proxy；策略优化需要防止过度偏离 reference。
DPO

Preference pairs → direct objective

在特定 formulation 下直接优化 preference，不单独训练 RM 再跑 PPO。
ORIGINAL GRPO

Group samples → relative advantage

原始 DeepSeekMath GRPO 用组内 reward 统计建立相对 advantage，避免单独 critic/value model。
保护指标

Preference win-rate 上升时仍要单独保护 factuality、task success、safety 和 calibration；代理指标变好不等于真实目标全都变好。

1.7 Hallucination：Plausibility 天生存在，Truthfulness 需要工程化

Hallucination 可能来自参数知识缺失/过时、Prompt 不完整、Retrieval 失败、Context 冲突、Tool Result 错误、unsupported inference，或系统本应拒答却强迫模型继续生成。

缓解方式获得什么付出什么
Grounding / RAG外部 Evidence 与可更新事实检索延迟、索引维护、Context Token、召回失败
Scope + Abstention不确定时不猜Coverage 下降与 false refusal
Verification / Tool外部检查或 deterministic evidence额外延迟、成本和 verifier failure

1.8 Prompt vs RAG vs Fine-tuning：先诊断 Failure Type

问题类型首选杠杆为什么
指令 / 风格 / 输出格式Prompt / Few-shot最快、最便宜、最容易回滚
缺少动态 / 私有 / 可追溯事实RAG / Tool / External Context知识可更新、可授权、可引用
长期重复的行为缺口Fine-tuning / Adaptation把稳定行为模式写入模型参数
模型能力上限更强/更专用模型或架构变化Prompt 不能制造不存在的能力
记忆法

Prompt for behavior · RAG for changing evidence · Fine-tuning for repeated behavior.

LoRA 通过冻结 base weights、训练低秩更新矩阵来降低可训练参数量；QLoRA 把 quantized frozen base 与 LoRA adapters 结合。4-bit weights 不代表总训练内存一定缩小 4 倍，因为 activations、optimizer、adapter 和临时 buffer 仍然存在。

1.9 Structured Output：结构正确不等于任务正确

Prompt-only JSON
→ JSON mode
→ strict schema / constrained decoding
→ semantic validation
→ permission / risk gate
→ host execution

当前 OpenAI Structured Outputs 在支持的 API / JSON Schema subset 上可以使用 strict schema 约束结构；JSON Mode 只保证有效 JSON。无论哪一种，都不能把 schema-valid 直接当成 factually correct、business-valid 或 authorized。

三层边界

Syntax validity ≠ semantic validity ≠ authorization.

1.10 Latency 与 Cache：先分解链路

Client / Network
→ Gateway / Queue
→ Prompt Assembly / Retrieval
→ Prefill / TTFT
→ Decode
→ Tool / Validation
→ Final Delivery

高价值优化通常来自：减少输出 Token、在质量允许时用更小/更快模型、减少无效输入、减少串行请求、并行独立步骤、复用缓存。Streaming 主要降低 perceived latency，并不一定降低总计算或 task completion time。

Cache复用什么主要边界

1.11 Model Selection 与 Migration Eval

模型选择是多目标工程决策：Task quality、modality、tool/structured-output support、context behavior、latency、throughput、cost、privacy、hosting、version lifecycle 都需要进入 Task Contract。Self-host 也不能只比较 GPU 小时价与 API Token 价，还要计算 utilization、capacity headroom、SRE、安全、升级、可用性和质量差距。

Production baseline
→ frozen eval set
→ candidate model replay
→ per-example + slice diff
→ tool/schema compatibility
→ latency + cost
→ shadow / canary
→ ship / hold / rollback
发布原则

Model behavior is a versioned dependency; treat migration like a production release.

1.13 Canonical Rules

必须记住

Characters are a UI quantity; tokens are a model-runtime quantity.

A long context window is capacity; evidence utilization is empirical.

Sampling controls variability; it does not create truth.

Semantic similarity is candidate generation, not correctness.

Syntax validity is not semantic validity, and semantic validity is not authorization.

Capacity, selection, and reuse are separate design axes.
