CHAPTER02

企业检索基础

EXACT · BM25 · DENSE · GRAPH · METADATA
WWHYWWHENPPITFALL

企业 RAG 常见的五种检索能力不是互相替代，而是解决不同问题：标识符、术语、语义、关系、范围。

EXACT
对结构化字段 / 规范化字符串做确定性匹配。keyword field、term query、PK lookup、hash、alias。
适合
订单号 · 错误码 · 零件号 · VIN · SKU · API 名 · 版本号
BM25
倒排索引，词法相关性排序：词频、稀有度、文档长度。
适合
专业术语 · 产品名 · 错误描述 · 技术 / API / 法规文档 · 函数名
DENSE
Query 与文档编码为 Embedding，向量相似度找语义接近内容。
适合
自然语言问答 · 口语化 · 同义词 · 用户不懂术语 · 跨语言
GRAPH
不搜“哪段文字最像”，而是沿实体关系找答案。Neo4j / SPARQL / Property Graph。
适合
BOM · ERP/PLM · 组织结构 · 依赖 · 多跳推理 · 影响分析
META
本身不理解答案，负责先缩小搜索范围。
字段
tenant · role · country · language · doc type · version · effective date · 密级
能力原理优势局限 / 陷阱
Exact字段确定性匹配快、稳定、可解释不懂改写与同义；“精确”通常也需要规范化（E4307 / E-4307 / Error E 4307 → uppercase、去空格、连字符、alias）
BM25词法匹配 + 相关性排序快、便宜、可解释、对稀有词敏感不理解语义；“How can I get my money back?” vs “Refund and reimbursement policy” 词重合少则召回差；不是主键查询
DenseEmbedding 向量相似度处理改写、发现词面不同但语义相近的内容对编号 / 版本号不稳；cancel subscription 与 renew subscription 主题相近但动作相反；换模型需重建索引
Graph实体关系遍历多跳与影响分析：Supplier A → Material X → Product Y需先建实体与关系；实体消歧与更新成本高
Metadata属性过滤降无关召回、防旧版本污染、多租户隔离、改善延迟成本字段设计依赖治理能力；过滤过严会漏召回

必背 ×3

Exact retrieval is best for identifiers, but it usually requires field-aware indexing and normalization.

BM25 handles lexical relevance; it is strong for terminology but weaker for paraphrases.

Dense retrieval handles meaning, but semantic similarity is not the same as factual or operational equivalence.

关键原则

Authorization before semantic similarity. 未经授权的文档不应进入模型上下文。
