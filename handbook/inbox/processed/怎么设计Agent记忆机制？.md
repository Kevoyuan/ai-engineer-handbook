## 原始材料（逐字保留）



2026年AI行业面试，问你怎么设计Agent记忆机制，面Agent开发是吧。 咱们做的这个Agent要长期服务客户，你怎么能保证它记住客户几年前说过的事？

很多人上来就说：上向量数据库，历史对话存进去，然后查的时候找最相似的。 那客户3年前说发票要寄到上海办公室，今年月初又说公司搬到杭州总部了，两条都搜出来了，该信哪条？ 两条都给Agent看，让它自己判断？只会说向量库三个字，面试官一问矛盾记忆怎么处理，你直接答不上来。

今天我把完整的面试高分回答给你捋清楚。 核心一句话：Agent记忆不是简单存聊天记录，是**分层记忆架构 + 记忆生命周期管理（写入、召回、更新、遗忘）**。

## 第一层：工作记忆（短时记忆 / Working Memory）

就是当前上下文窗口里面的内容，直接喂给大模型，读写最快、容量最小。 里面放三样东西：

1. 系统Prompt
2. 最近N轮原始对话
3. 当前任务状态、规划、工具返回结果、待办进度

它的作用，保证本轮、连续几步任务的连贯性，解决指代、上下文承接。 痛点：token有上限，不能无限堆。 超限处理方案二选一：滑动窗口 / 摘要压缩summarize，不重要信息移出上下文。

> 重点：这一层是推理必须的，所有思考、工具调用都依赖它。

## 第二层：中期会话记忆（会话摘要记忆）

单轮会话、同一个任务还没结束，但是对话很长，不适合全留在工作记忆。 每一轮或者固定轮数之后，用模型把对话提炼成结构化摘要： 用户诉求、已完成动作、中间结论、约束条件。 原始对话可以归档，摘要保留。 一般存在Redis这类缓存，会话结束或者超时之后可以清理。 它介于工作记忆和长期记忆中间，用来减少工作记忆的token压力，同时保留本次任务主线。

## 第三层：长期记忆（跨会话记忆）

跨天、跨次对话都要保留的信息，这才是大家说的向量库这一层，但**不能一股脑全塞**。 长期记忆内部继续拆三类（对标人脑认知记忆，面试加分项）：

1. **语义记忆**：事实、用户固定偏好、业务规则、静态知识（比如用户收件地址、口味偏好、权限），优先结构化存储（MySQL/JSON），同时做向量索引。
2. **情景记忆**：过往发生的事件、交互历史、某次任务完整过程，没有办法结构化的，切片段向量化存入向量库。
3. **程序记忆**：固化的流程、SOP、工具使用经验，Agent学会的一套做事步骤，下次同类任务直接复用规划，不用从头推理。

## 四大生命周期（拉开差距的核心，90%候选人不讲）

### 1. 写入策略：不是每一句话都入库

- 主动触发写入：用户明确说“记住xx”，立刻落库，高优先级；
- 异步总结写入：对话结束、任务完成之后，后台抽取关键信息入库；
- 过滤机制：闲聊、无效废话不写入长期记忆。

### 2. 召回策略：不是只看向量相似度

混合召回：向量相似度 + 时间衰减权重 + 记忆重要性打分 + 关键词检索。 核心目标：召回**当下任务最相关、最新有效**的记忆，而不是单纯最相似的。 刚才那个地址矛盾的例子：新记忆时间戳更新，旧记忆标记过期，召回的时候优先最新版本。

### 3. 更新策略（解决冲突记忆的关键！面试官最爱追问）

不能新增一条、新旧两条并存打架。 有新事实和旧记忆冲突时： 更新原有记忆，打上最新时间戳、版本标记，旧记忆归档、降级，不再优先召回。 而不是无脑追加。

### 4. 遗忘策略（非常关键）

记忆库无限膨胀，召回噪声爆炸，必须遗忘：

- 时间遗忘：超过有效期自动归档/删除；
- 重要性遗忘：打分低、长期没有被召回过的记忆逐步衰减；
- 容量阈值遗忘：库满的时候淘汰权重最低的记忆。

## 最终Prompt拼装方式（回答收尾）

每次推理前，拼装顺序： 系统提示词 + 当前工作记忆（最近对话+任务状态） + 召回筛选后的长期记忆片段。 不是把所有历史都塞进去。

## 避坑总结（面试收尾升华）

很多Demo版本的Agent，只有向量库，缺少分层、缺少更新遗忘，很容易出现记忆冲突、幻觉、越跑越乱。 生产级Agent记忆的难点，**不是怎么存，而是怎么筛选、怎么更新矛盾信息、怎么遗忘无效信息**。

## 面试官高频追问预演（配套）

Q1：滑动窗口和摘要压缩分别适合什么场景？ A：滑动窗口实现最简单，适合短对话、交互频次高；摘要压缩适合长任务，但是压缩会丢失细节，需要权衡，也会影响前缀缓存命中。

Q2：结构化存数据库 和 向量库怎么分工？ A：确定的实体、事实偏好放关系库，精准查询；模糊经验、情景片段放向量库做语义召回，两者配合混合检索。

Q3：记忆遗忘会不会丢失有用信息？ A：不是硬删除，一般是降级归档，需要的时候仍然可以检索，只是默认召回优先级降低。

# 面试精简口述版（直接背）

面试官你好，我设计Agent记忆会采用三层分层架构，配套完整的记忆生命周期管理。 第一层是工作记忆，就是当前上下文窗口，放系统提示词、最近对话、任务状态，保障实时推理，容量有限，超限后用滑动窗口或者摘要压缩控制token； 第二层是会话中期摘要记忆，同一会话内提炼任务主线摘要，放到缓存，减轻上下文压力； 第三层是跨会话长期记忆，拆成语义记忆、情景记忆、程序记忆，分别存事实偏好、历史事件、流程经验，结合数据库+向量库存储。 同时我会做写入、召回、更新、遗忘四套机制：选择性写入，混合方式召回，遇到冲突记忆直接更新版本而不是追加，基于时间、重要性做记忆衰减遗忘，避免记忆污染和无限膨胀。最后推理的时候，把召回后的记忆和当前工作记忆组合送入模型，而不是全量历史拼接。
