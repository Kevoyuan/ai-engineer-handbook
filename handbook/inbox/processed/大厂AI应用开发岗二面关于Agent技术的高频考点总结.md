## 原始材料（逐字保留）

### 一、项目与业务落地类

1. 请介绍一个你做过的Agent项目，说明项目背景、解决的业务问题，以及为什么选择Agent方案而非普通Workflow或传统后端服务。
2. 项目上线前后业务指标有哪些变化？如果重新做这个项目，你会做哪些改进？
3. 如何判断一个场景是否适合投入Agent开发，还是应该使用传统工程方案？
4. Agent技术在实际业务落地中最大的限制是什么？哪些问题可以通过工程化手段解决？

### 二、生产环境与问题排查类

1. 在生产环境中，Agent最难解决的问题是什么？请说明具体现象、发现方式、根因定位方法，以及最终的架构调整方案。
2. 生产环境中出现延迟突然升高、成本增加的情况，你会如何定位问题？
3. 上线后发现效果下降，你有哪些快速回滚预案？

### 三、Agent执行与可靠性类

1. 你们如何定义Agent任务成功率？上线后实际成功率是多少？
2. 如何统计工具调用失败率？哪类任务最容易失败？对应的优化手段是什么？
3. 当复杂任务出现时，Agent的执行流程是怎样的？哪些部分由模型决定，哪些部分由代码控制？
4. 如何防止Agent循环调用工具？如果执行过程中发现原计划不合理，如何调整？
5. 模型连续调用多个工具时如何处理？如果某个工具执行失败，如何处理已成功的结果？
6. 哪些失败场景可以重试，哪些不能？重试时如何避免产生外部副作用？
7. 如何保证Agent每个步骤执行结果的可信性？如果某一步成功后续步骤失败，如何恢复？
8. 哪些步骤必须由业务代码控制？

### 四、工具调用与容错类

1. 线上遇到过模型选错工具或参数生成错误的问题吗？如何解决？
2. 参数格式正确但业务含义错误时如何处理？
3. 模型调用不存在的工具时，系统如何兜底？
4. 如何防止模型调用用户没有权限的工具？
5. 如何控制单次任务的最大执行时间和模型调用次数？做过哪些优化？优化前后的指标变化是怎样的？
6. 模型调用工具时是否做了幂等性控制？

### 五、框架与扩展类

1. 你使用过哪些Agent框架？选择框架的出发点是什么？
2. 框架帮你解决了哪些问题？哪些能力需要二次开发？
3. 当框架执行逻辑不符合业务需求时，如何扩展？

### 六、知识库与上下文类

1. 知识库召回正确但模型回答错误时如何处理？
2. 上下文过长导致关键内容被截断时如何处理？
3. 如何解决新旧文档冲突的问题？
4. 上下文压缩和结构化检索的优势是什么？
5. 什么场景下会放弃模型回答，转而调用业务接口？

### 七、记忆与多轮对话类

1. 业务Agent如何管理多轮对话和长期记忆？
2. 历史对话是直接放入上下文，还是经过筛选压缩？
3. 哪些信息值得长期记忆？
4. 如何避免不同用户、不同项目之间的记忆串扰？

### 八、多Agent相关类

1. 你使用过多Agent方案吗？为什么选择多Agent而非单Agent？解决了什么问题？
2. Agent之间如何传递上下文和任务结果？
3. 如何避免多个Agent重复执行相同工作？
4. 引入多Agent后，成本、延迟、成功率有什么变化？

### 九、版本与评估类

1. 如何评估Agent版本升级后对业务的实际提升？
2. 是否在生产环境构建评测集？如何比较不同模型、PE和工具描述的效果？

### 十、架构与管理类

1. 哪些业务Agent能力必须由团队自研？
2. 如何解决多租户隔离、模型路由和成本控制问题？
